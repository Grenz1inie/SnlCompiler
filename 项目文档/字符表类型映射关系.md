# SNL Compiler Token `type` 数字映射

这里说的不是语义分析后符号表里的 `Type` 列，而是词法分析产出的 `Token.i`。

## 映射关系

| `Token.i` | 含义 | 代码来源 |
| --- | --- | --- |
| `1` | 分隔符 / 符号 | `Lexer.appendWord()` / `Lexer.doToken()` 中用 `new Token(1, ...)` 构造 |
| `2` | 保留字 | `Lexer.appendWord()` 中 `new Token(2, idx, line)` |
| `3` | 标识符 | `Lexer.appendWord()` 中 `new Token(3, idx, line)` |
| `4` | 数字常量 | `Lexer.appendWord()` 中 `new Token(4, idx, line)` |
| `5` | 字符常量 | `Lexer.doToken()` 中 `new Token(5, idx, line)` |

## 说明

- `Token.i` 的注释在 [`Token.java`](SnlCompiler-Backend/src/main/java/com/snl/compiler/domain/token/Token.java) 里写得很直接：`1` 分隔符，`2` 保留字，`3` 标识符，`4` 数字常量。
- `5` 是字符常量，虽然 `Token.java` 注释没写全，但 `Lexer` 里明确用了 `new Token(5, ...)`。
- `Token.j` 不是类型，而是下标：
  - `1` 时，`j` 指向 `Constants.separator`
  - `2` 时，`j` 指向 `Constants.reservedWord`
  - `3` 时，`j` 指向 `Lexer.identifier`
  - `4` 时，`j` 指向 `Lexer.INTC`
  - `5` 时，`j` 指向 `Lexer.CHARC`

## 对应输出

`TokenMapper.resolveLexeme()` 会把 `Token.i` 和 `Token.j` 还原成可读文本，输出到前端。

```java
switch (token.i) {
    case 1: return Constants.separator.get(token.j);
    case 2: return Constants.reservedWord.get(token.j);
    case 3: return Lexer.identifier.get(token.j);
    case 4: return Lexer.INTC.get(token.j);
    case 5: return Lexer.CHARC.get(token.j);
    default: return "";
}
```

## 例子

- `program` -> `Token(2, idx, line)`
- `p` -> `Token(3, idx, line)`
- `:=` -> `Token(1, idx, line)`
- `10` -> `Token(4, idx, line)`
- `'a'` -> `Token(5, idx, line)`
